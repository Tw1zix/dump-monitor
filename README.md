# Мониторинг несанкционированных свалок

Веб-приложение для поиска мусора на видео с дрона. Нейросеть YOLOv8 находит свалки на кадрах, телеметрия RTK из файла SRT привязывает находки к координатам, а результат собирается на карте, в реестре и в отчётах.

## Возможности

- Загрузка видео с дрона и (по желанию) файла телеметрии `.srt`
- Автоматический поиск мусора обученной моделью `models/best.pt`
- Привязка находок к RTK-координатам: координата считается для самого объекта (по положению рамки в кадре, высоте и курсу), а не для дрона. Повторные находки одной и той же кучи отсеиваются
- Карта: схема и спутник, кластеры точек, слой плотности, охранные зоны
- Таблица «Свалки»: близкие находки (до 20 м) объединяются в одну свалку, с пометкой охранных зон и ссылкой на маршрут
- Реестр находок с фильтрами, просмотром снимка и статусами: новая, проверена, подтверждена, ложная
- Экспорт: CSV, GeoJSON, снимки ZIP, отчёт для печати (PDF через браузер), резервная копия, ложные срабатывания для дообучения
- Очередь заданий, остановка обработки, оценка оставшегося времени
- Папка-приёмник `inbox/`, уведомления в Telegram, светлая и тёмная тема

## Установка

Нужен Python 3.12 или 3.13.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Установка идёт долго: `ultralytics` тянет за собой PyTorch (1–2 ГБ). Если на Python 3.13 установка PyTorch не удалась, создайте окружение на Python 3.12.

Положите обученные веса в `models/best.pt`. Без этого файла детектор переходит в демо-режим и показывает ненастоящие находки. Строка `[detector] YOLO загружена` в консоли при первой обработке подтверждает, что модель подхвачена.

## Запуск

```powershell
python app.py
```

Откройте `http://127.0.0.1:5000`. В PyCharm достаточно запустить `app.py` (зелёный треугольник).

## Как пользоваться

1. **Обработка записи.** Выберите видео (MP4, MOV, AVI, MKV) и при наличии файл `.srt`. Задайте интервал проверки кадров (по умолчанию 1000 мс) и порог уверенности (по умолчанию 0.4). Нажмите «Запустить обработку».
2. **Карта находок.** Точки видны только у находок с координатами, то есть когда загружен SRT. Слои меняются в правом верхнем углу карты.
3. **Отчёты.** Здесь свалки, реестр находок, задания и все кнопки экспорта. Клик по снимку открывает просмотр, где можно сменить статус находки.
4. **Охранные зоны.** Кнопка «Загрузить зоны» принимает файл GeoJSON с полигонами. Название зоны берётся из поля `name`. Файл KML нужно сначала перевести в GeoJSON (например, в QGIS).

### Папка-приёмник

Видео (и файл `.srt` с тем же именем), положенное в `inbox/`, само встаёт в очередь с настройками по умолчанию. Обработка стартует через 10–20 секунд, когда файл докопируется.

## Формат SRT

Из файла читаются поля вида `[latitude: ..]`, `[longitude: ..]`, `[rel_alt: ..]` (или `[altitude: ..]`), `[timestamp: ..]` в миллисекундах, `[rtk_status: ..]`, а также `[gb_yaw: ..]` (курс подвеса) и `[gb_pitch: ..]` (наклон подвеса, -90 означает «строго вниз»). Это формат телеметрии DJI с RTK. Значение RTK `fix` или `float` показывается в интерфейсе, всё остальное считается «Нет RTK».

## Как считается координата находки

Координата в SRT это положение дрона. Чтобы получить положение мусора, `geo.py` смещает её по положению рамки в кадре: размер кадра на земле считается по высоте и углу обзора камеры, направление по курсу `gb_yaw`.

Поправка применяется только если камера смотрит вниз (наклон подвеса от -80° до -90°) и в SRT есть высота, курс и наклон. Иначе берётся позиция дрона без поправки. Высота `rel_alt` отсчитывается от точки взлёта, поэтому на неровном рельефе возможна ошибка. Угол обзора камеры задаётся переменной `CAMERA_HFOV_DEG`, её нужно подставить под вашу модель дрона.

## Настройки (переменные окружения)

| Переменная | Что делает |
|---|---|
| `HOST` | адрес сервера, по умолчанию `127.0.0.1` (только этот компьютер). `0.0.0.0` открывает доступ из сети |
| `APP_PASSWORD` | если задан, сайт просит пароль (имя пользователя любое) |
| `KEEP_UPLOADS` | `1` — не удалять видео и SRT после обработки |
| `TELEGRAM_TOKEN`, `TELEGRAM_CHAT` | токен бота и chat id для уведомлений о завершении обработки |
| `CAMERA_HFOV_DEG` | горизонтальный угол обзора камеры в градусах, по умолчанию 70. Влияет на точность координат |
| `MODEL_PATH` | путь к другим весам вместо `models/best.pt` |
| `IMGSZ` | размер изображения для модели (по умолчанию 640) |
| `DEVICE` | `cpu` или номер видеокарты, например `0` |

В PyCharm переменные задаются в `Run → Edit Configurations → Environment variables`.

## API

| Метод и путь | Назначение |
|---|---|
| `POST /api/upload` | загрузка видео и SRT, возвращает `job_id` |
| `GET /api/job/<id>` | статус задания |
| `POST /api/job/<id>/stop` | остановить обработку |

| `GET /api/detections` | все находки |
| `POST /api/detection/<id>/status` | сменить статус (`new`, `checked`, `confirmed`, `false`) |
| `POST /api/detection/<id>/delete` | удалить находку |
| `GET /api/sites` | свалки (сгруппированные находки) |
| `GET, POST /api/zones` | охранные зоны (GeoJSON) |
| `GET /api/report` | сводка и список заданий |
| `GET /api/export/csv`, `/api/export/geojson`, `/api/export/false` | экспорт |
| `GET /api/download/zip`, `/api/backup` | снимки ZIP, резервная копия |
| `GET /report/print` | страница отчёта для печати |

## Ограничения

- Точность координат зависит от курса, наклона подвеса и угла обзора. При наклонной камере координата это позиция дрона, ошибка может достигать десятков метров.
- Без SRT у находок нет координат: карта, свалки и охранные зоны остаются пустыми.
- Отсев дублей без SRT идёт по перекрытию рамок на соседних кадрах. Если дрон летит быстро, часть повторов может остаться.
- Задания обрабатываются по одному. Задание, прерванное перезапуском сервера, помечается ошибкой.
- Карта, шрифты и библиотеки интерфейса подгружаются из интернета.

## Если что-то не работает

- `TemplateNotFound: index.html`: файл должен лежать в `templates/`.
- `ModuleNotFoundError`: зависимости установлены не в то окружение, проверьте, что активен `.venv`.
- `Address already in use`: порт 5000 занят, смените `port=5000` в последней строке `app.py`.
- `демо-режим` в консоли: модель не найдена по пути `models/best.pt`.
- `Fatal error in launcher` при `pip`: папку с `.venv` переносили, окружение нужно создать заново.
- `Missing dependencies for SOCKS support`: pip идёт через SOCKS-прокси, сбросьте переменные `ALL_PROXY` и `HTTPS_PROXY` или установите `PySocks`.
